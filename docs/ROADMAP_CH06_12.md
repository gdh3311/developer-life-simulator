### 3.1 증거 기록 `scripts/story/evidence.gd` (구현됨)

> 구현: `Story.evidence`. 1~6장 규칙 14개로 기존 세이브를 조용히 채우고(규칙은 한 번만 적용), 업무 완료와 폼 제출 때 갱신하며 바뀌면 "📒 내 기록" 알림을 띄운다. Dashboard의 "내 기록" 카드(`scripts/apps/evidence_panel.gd`)에 등급, 근거 업무, 처음 등급, 올리는 방법이 보인다. 뒤 챕터는 `Story.evidence.at_least(key, grade)`로 읽고, 결과로 등급을 바꿀 때는 `set_grade`(내릴 수 있음), 보완할 때는 `raise`를 쓴다. 테스트: `-Suite evidence`.

[장기 상태 설계](SCENARIO_CHARACTERS.md#장기-상태-설계)의 키를 실제로 저장한다.

- `Game.state["evidence"][key] = {"grade", "source", "history": [...], "checked_day"}`
- `Evidence.set(key, grade, source)`, `Evidence.grade(key)`, `Evidence.at_least(key, grade)`
- 등급은 키마다 순서가 있다(예: `handoff_quality`: personal < documented < rehearsed). 나중에 보완하면 등급은 오르지만 처음 기록은 `history`에 남는다.
- Dashboard에 "내 기록" 카드: 키마다 현재 등급, 근거 업무, "부족하면 이걸 하면 된다" 링크.
- **기존 세이브 보정:** 1~6장 업무 결과에서 초기 등급을 계산한다(예: C02 M06을 동시성 테스트로 통과 → `idempotency_evidence = concurrent`). 이미 끝낸 세이브도 7장부터 같은 규칙을 읽는다.

| `idempotency_evidence` | C02 M03·M06, C05 M04 | C11 M03 자동 격리 여부 |

### 3.2 동료가 올리는 PR `scripts/services/npc_pr.gd`

> 구현: `Story.npc_prs`. 미션은 `await Story.npc_prs.open("jw_shipping", mission_id)`로 PR을 열고 `npc_pr_resolved` 이벤트(`spec, mode, grade, learned, clean`)를 받는다. 처음 CI는 작성자 테스트만 돌고(초록), 플레이어가 답하면 `[CI]` 숨은 검사가 붙는다. 답은 세 가지다: 줄을 골라 댓글(버그 줄을 짚으면 맞게 고치고 `explained`, 못 짚으면 빗나간 수정이 숨은 검사에 걸려 다시 물어봄), 직접 고치기(그 브랜치에 push → `takeover`, 배운 것 없음), 함께 고치기(1시간, 이유를 설명하면 `explained`, 답만 주면 `takeover`). 확인 없이 LGTM하면 숨은 검사가 실패하고 Daniel이 돌려보낸다. 배운 교훈은 사람별로 저장되고, 같은 교훈을 `repeats`하는 다음 PR은 처음부터 맞게 와서 LGTM으로 병합하면 `independent`. 콘텐츠: `content/commerce-api/<lang>/npc/<spec>/`, 숨은 검사 `content/ci/<lang>/npc_<spec>/`, 생성기 `tools/gen_npc_pr_content.py`. 견본 PR 두 개(지우의 배송비 → 상자 수, 교훈 `partial_units`). 테스트: `-Suite npc_pr`.

7장의 핵심. 지금 CodeHub은 플레이어 PR만 다룬다.

- 콘텐츠 폴더에 `author`, `branch`, `diff`(파일 내용), `hidden_bug`(숨은 테스트), `needs`(설명이 필요한 지점)를 둔다.
- 플레이어는 CodeHub에서 세 가지 중 하나로 대응한다.
  1. **직접 고침** — 그 브랜치에 커밋한다. 빠르다. `mentoring_evidence = takeover`.
  2. **질문 댓글** — 줄에 댓글을 단다. 지우가 반나절 뒤 고친 커밋을 올린다. 댓글이 버그 위치를 짚지 못하면 고친 커밋도 빗나간다.
  3. **페어링** — 시간이 들고(시계가 1시간 감), 짧은 대화 선택 후 지우가 고친다. `explained`.
- 같은 사람이 다음 PR에서 같은 실수를 하는지가 `mentoring_evidence`를 정한다. 9장과 11장에서 지우가 혼자 하는 PR이 이 등급에 따라 성공한다(`independent`).
- 8장(AI PR), 10장(상대 회사 PR), 12장(신입 README PR)에서 재사용한다.

## 5. 챕터 하나를 만드는 순서

5장에서 쓴 방식을 그대로 표준으로 삼는다.

1. `docs/SCENARIO_CHAPTER_0N.md`: 장면, 대사 핵심, 업무 규칙, 실패 복구.
2. `tools/gen_chapterN_content.py`: ko/en 코드, 버그·수정·AI 변형, 숨은 테스트, CI 설정.
3. `scripts/story/missions/c0N_*.gd`: 업무 8개.
4. 필요한 화면(`scripts/apps/…`), 위키 문서, 브라우저 북마크.
5. 연결: `chapters.gd`, `story.gd` MISSIONS, NPC, 아크 비트, 이벤트 카드 4장, 책상 소품 해금.
6. 증거 기록: 이 장이 쓰는 키와 남기는 키.
7. `tests/chapterN_test.gd`: prevent/recover 두 프로필 + 증거 등급이 낮은 세이브.
8. 직접 플레이(챕터 시작 세이브 사용) → 시간 측정 → 조정.
