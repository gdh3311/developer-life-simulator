# Developer Life Simulator 챕터 1 검증 기록

기준일 2026년 11월 23일

첫 챕터의 예방, 장애 수습, 도움 사용과 재개 경로를 실제 Git·Node·PR 처리로 자동 실행했다. 조사 기능 검사와 합쳐 **272개 확인 항목이 통과했고, 최종 실행 로그에 스크립트 오류와 종료 경고가 없었다.**

자동 실행은 게임의 Terminal, DevIDE, AICode와 대화 선택 처리 함수를 호출한다. 파일 변경, 커밋, push, 숨겨진 CI, NPC 병합과 충돌 해결은 실제로 수행한다. 화면을 마우스로 조작한 사용성 검사나 처음 보는 사람의 재미 평가는 별도다.

## 고친 문제

### AI 사용과 재시도

AI 위임 완료 시 사용 횟수가 증가하지 않아 회고의 AI 선택지와 성과 대사가 누락되던 문제를 고쳤다. 같은 업무의 중복 위임도 차단한다. 다른 업무나 새 게임으로 바뀐 뒤 이전 AI 작업이 파일을 적용하지 않도록 확인한다.

쿠폰 리뷰에서 근거 없는 줄을 선택하면 다시 검토하라는 답장은 오지만 UI의 리뷰 권한은 닫혀 있던 문제를 고쳤다. 이제 수정한 의견을 다시 제출할 수 있다. 이미 처리한 리뷰의 중복 제출은 거절한다.

첫 PR은 실제 README 수정이 없어도 CI가 통과하면 승인되던 상태였다. 이제 원격 PR의 README를 확인하고 누락된 수정에는 변경 요청을 남긴다. 관련 없는 커밋만으로 수정 목표를 완료하지 않는다.

### 미션과 CI 재개

진행 중 미션의 `resume`이 비어 있어 처음 안내, NPC 답변과 일부 마무리 장면이 돌아오지 않던 문제를 고쳤다. 도입 완료 여부, 준비 상태, 보낸 메시지와 적용한 보상을 저장하며 필요한 단계부터 재개한다.

장면이나 언어를 다시 불러올 때 이전 미션 객체의 지연 작업을 무효화한다. 새 게임에 이전 환영 메시지가 나타나지 않는 것을 확인했다. 병합 직후 저장된 경우에도 완료로 이어지고 관계 보상을 두 번 주지 않는다.

저장된 `running` CI와 `merging` 상태를 복원한다. 원격 main에 이미 반영된 PR은 Git 이력으로 확인하고, 남은 PR은 현재 상태를 검증한다. 이전 실행의 결과와 같은 커밋의 중복 실행이 최신 결과를 덮지 않도록 실행 세대를 구분한다.

테스트 결과가 끝나도 병합 가능성 확인이 남아 있는 동안에는 CI를 완료 상태로 노출하지 않는다. 이 순서에서 발생하던 중복 시간·통계 반영을 고쳤다. 이미 집계한 CI 결과를 재개 목적으로 검증할 때 시간을 다시 청구하지 않는다.

끝난 첫 챕터를 불러왔을 때 엔딩 상태가 복원되지 않아 불필요한 다음 근무일로 넘어갈 수 있던 문제를 고쳤다.

### 저장과 작업 파일

저장 버전 1을 추가하고 버전이 없는 기존 저장을 기본값과 병합해 읽는다. JSON과 핵심 필드의 형태를 확인한 뒤 적용하며 읽기 실패가 현재 상태를 먼저 지우지 않게 했다.

새 저장은 `save.json.tmp`에 쓰고 검증한 뒤 교체한다. 이전 유효 저장은 `save.json.bak`에 남긴다. 손상된 본 파일을 복구한 뒤 다시 저장해도 정상 백업을 손상 파일로 덮지 않는다. 보존한 손상 파일은 `.corrupt`로 남긴다.

주 저장이 손상되거나 교체 중 사라진 경우 백업을 읽는다. 더 새로운 버전의 주 저장은 오래된 백업으로 조용히 대체하거나 덮어쓰지 않는다. 두 파일을 읽지 못하면 게임 시작을 멈추고 재시도와 두 번 확인하는 초기화 선택을 제공한다.

저장소와 진행 파일 중 한쪽만 있는 경우도 기존 데이터를 임의로 새 게임으로 덮지 않는다. 저장된 Git 체크포인트와 현재 상태가 다르면 파일과 커밋을 유지하고 이를 알린다. 실제 재마운트 검사에서 미커밋 파일이 보존됐다.

급여는 하루 한 번만 지급하며 엔딩 재진입과 중복 날짜 전환으로 중복 수령하지 않는다. Git·테스트 작업이 실행 중일 때는 새 게임 초기화를 거절한다.

### 명령과 종료

튜토리얼의 Git 설정과 이력 확인, 브랜치 정리는 명령 입력 전이 아니라 실행 결과를 받은 뒤 판정한다. 설정을 읽는 작업이 쓰기보다 먼저 끝나면서 목표를 놓칠 수 있는 순서를 바로잡았다.

커밋 통계는 실제 커밋을 만드는 명령으로 제한했다. 재시작 뒤 예전 브랜치를 체크아웃하는 것으로 새 커밋을 만들었다고 판정하지 않는다. IDE의 백그라운드 갱신과 명령 실행이 겹쳐도 명령 전 상태를 기준으로 비교한다.

외부 프로세스 시간 제한은 게임 속도와 분리하고 종료한 작업의 타이머를 해제한다. 현재 실행 작업 수를 추적해 테스트 종료 전 정리한다. 오디오 재생과 합성 스레드도 종료 시 정리해 자동 실행에서 확인된 리소스 경고를 제거했다.

## 재현 방법

저장소 루트의 PowerShell에서 설치된 Godot 콘솔 실행 파일을 지정한다. 아래 `$godotPath`는 로컬 설치 위치에 맞춘다.

```powershell
$godotPath = 'C:\path\to\Godot_v4.7.2-stable_win64_console.exe'
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Screenshots
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter -Profile prevent
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter -Profile recover
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter -Profile resume
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite recovery
```

각 실행은 고유한 임시 프로젝트와 Godot 사용자 데이터 영역을 만든다. 플레이어의 실제 저장과 회사 저장소를 읽거나 지우지 않는다. 재시작 경로는 같은 테스트 프로젝트를 여러 프로세스에서 이어서 실행한다.

로그와 조사 화면은 `build/gameplay-qa`, `build/chapter-qa`, `build/recovery-qa`에 생성한다. 챕터 실행에는 확인 항목, 미션 상태와 통계가 담긴 JSON 기록도 남긴다. 컴파일 오류는 실행 전 검사에서 걸러 내고, 실행 결과에 오류가 남으면 실패 처리한다.

## 검증의 범위와 다음 작업

프로세스를 실제로 교체해 저장된 미완료 상태의 재개를 확인했다. 종료 전 테스트 자식 프로세스는 정리한다. 전원 차단이나 Git 쓰기 도중의 강제 종료, 디스크 가득 참, 파일 잠금과 하드웨어 장애까지 재현한 결과는 아니다.

수동으로 확인할 항목은 창 조작과 입력 포커스, 실제 설정 화면의 언어 전환, 미저장 편집 내용의 처리, 첫 사용자에게 보이는 안내와 플레이 속도다. 외부 배포 전의 OS 격리와 런타임 동봉도 남아 있다.

후속으로 챕터·서사 시간·실행 일차를 분리하고, 기존 챕터 1 저장에서 챕터 2 첫 세 업무로 이어지는 구조를 구현했다. 새 구간의 범위와 검증은 [챕터 2 기록](QA_CHAPTER_02.md)에 정리한다. 신규 진행의 Brightloop 선택은 면담 지속이며, 기존 저장의 정식 오퍼 선택은 보존한다.
