# 챕터 2 첫 구간 구현과 검증

기준일 2026년 11월 23일 · 내부 개발용

챕터 1 완료 저장에서 챕터 2의 **고객 기록 조사 → 지연·재전송 재현 → 순차 중복 방지**로 이어지는 첫 3개 업무를 구현했다. 한국어 직접 수정 경로와 영어 AI 도움 경로의 신규 검사 **140개가 통과**했다. 기존 기능·챕터 1 두 경로·저장 복구 218개를 다시 검사해 이번 묶음은 **총 358개 확인 항목, 실패 0개**다. 마지막 실행 로그에 스크립트 오류와 종료 경고가 없다.

이 수치는 자동 확인 항목의 수다. 처음 보는 플레이어의 재미나 수동 마우스·키보드 조작을 평가한 결과는 아니다. 챕터 2의 전체 8개 업무 중 3개만 제공하며, Steam 배포 빌드는 아직 만들지 않았다.

## 구현 범위

| 구간 | 현재 동작 | 남은 범위 |
|---|---|---|
| 챕터 전환 | 완료 결과의 시작 버튼, 기존 상태 보존, 실행 일차와 서사 월·요일 분리 | 후반 챕터의 역할·회사 전환 |
| C02 M01 / NXR-021 | 달빛상점 티켓, 내부 요청 기록, 비교할 재현 조건 기록 | 고객에게 추가 질문하는 분기, Yuri 등장 |
| C02 M02 / NXR-022 | Git으로 요청 모듈 받기, 지연·재전송·키·클릭 수 실험 | 동시 호출과 실제 네트워크 실험 |
| C02 M03 / NXR-023 | 순차 요청 계약, 공개 테스트 5개와 추가 CI 4개, PR·동료 검토, 현재 코드 재현 확인 | 동료 페어링, 동시성, 생성 실패 복구와 고객 적용 |
| 현재 구간 종료 | 3/8 제공 범위와 남은 작업 안내, 파일·기록 복습 | M04~M08 및 챕터 전체 마무리 |

새 `Request Lab`은 조건에 따라 실제 `src/orders/request.ts`의 `createOrder`를 Node로 실행한다. 지연은 가상으로 재전송을 예약하는 조건이다. 실제 인터넷이나 결제를 사용하지 않는다. 실험마다 별도 메모리 저장소를 사용하며 호출 횟수·생성 수·각 주문 번호를 보여 준다.

| 같은 구매 시도, 클릭 1회 | 호출 | 수정 전 주문 | 순차 수정 후 주문 |
|---|---:|---:|---:|
| 즉시 응답 | 1 | 1 | 1 |
| 응답 지연, 재전송 켬, 같은 키 | 2 | 2 | 1 |
| 응답 지연, 재전송 끔 | 1 | 1 | 1 |
| 응답 지연, 재전송 켬, 매번 새 키 | 2 | 2 | 2 |

실험은 신고된 버전과 현재 작업 파일 중 고를 수 있다. 신고된 버전을 실행해도 작업 파일은 바꾸지 않는다. 실험 이력과 조건·코드 해시가 저장되며, 현재 코드 검증 후 IDE에서 수정하면 이전 검증 목표를 해제한다. 로컬 실험과 테스트가 맞더라도 검토된 PR 없이 업무를 끝내지 않는다.

순차 재전송, 빈 키, 상점과 키의 경계, 요청 내용 충돌이 공개 정책이다. CI는 같은 정책의 추가 입력을 독립 저장소로 검사한다. 동시 요청은 아직 계약에 포함하지 않으며, 마지막 Monitor 상태도 고객 환경 적용을 마친 정상 상태로 바꾸지 않는다.

## 저장과 기존 선택

실행 일차 1~4와 기존 미션 ID를 유지한다. 일차 5는 챕터 2의 두 번째 달 월요일로 표시한다. Dashboard 진행도는 현재 챕터 기준이며, 제공 업무 수와 계획 업무 수를 함께 표시한다.

버전 1 저장에 `request_lab` 기본값을 추가한다. 기존 직급·관계·돈·구매·미션 기록·선택을 초기화하지 않는다. 형식이 잘못된 실험 기록은 UI에 전달하기 전에 저장 읽기 검증에서 거절한다. JSON 숫자가 읽기 후 실수형으로 바뀌어도 유효한 정수 조건은 유지한다. 기존 백업·손상 파일 보존 정책을 사용한다.

신규 진행에서 Brightloop의 마지막 제안은 **면담 지속**이다. 호환성을 위해 기존 `ending` 값은 두고 `offer_stage=interview`로 구분하며, 실제 이직이라고 안내하지 않는다. 기존 정식 오퍼 수락 저장은 변경하지 않고 다음 구간을 이직 전 업무 기록으로 안내한다. 장편 전체의 회사 이동은 후속 제작이다.

챕터 1 결과와 현재 구간 정리를 반복해서 열어도 같은 날 급여를 다시 주지 않는다. 시작 버튼의 중복 호출도 날짜를 두 번 넘기지 않는다. 챕터 2 첫 구간을 끝내면 미구현 일차 6으로 진행할 수 없다.

| 실행 | 확인 항목 | 결과 |
|---|---:|---|

| 한국어, 재시작 → 원인 분리 → IDE 수정·PR·CI·마무리 | 37 | 통과 |
| 영어, 기존 정식 오퍼 수락 저장 → 조사·중복 재현 → 프로세스 종료 | 33 | 통과 |

| 합계 | **358** | **실패 0** |

챕터 2 검사는 기존 완료 저장의 경계를 구성한 fixture에서 출발한다. 챕터 1 전체 진행은 별도 두 경로에서 실제로 실행했다. 하나의 연속 프로세스에서 챕터 1 시작부터 챕터 2 끝까지 수동 완주한 결과로 표현하지 않는다.

자동 실행은 게임의 Desktop 전환, Terminal, DevIDE, AICode 처리 함수를 호출한다. Git 커밋·pull·push, Node 테스트, CI와 동료 병합은 실제로 수행한다. 잘못된 재현 계획, 유효하지 않은 실험 조건, 원본 코드의 테스트 실패, 잘못된 주문 반환값이 기록·저장을 깨뜨리지 않는 처리, 수정 후 검증 무효화, 원본 버전 보존, 새 키의 별도 구매, 중복 보상 방지도 포함한다.

두 언어의 티켓·중복 결과·수정 결과·구간 정리와 기존 결과 화면을 Godot로 렌더해 확인했다. 화면 밖으로 넘치는 본문은 스크롤 영역에 둔다. 실제 창 이동·포커스·키보드만으로 조작하는 검사는 별도로 남는다.

콘텐츠 14개 파일은 두 언어 템플릿과 일치하며, 기존 전체 콘텐츠 생성기에서도 같은 결과를 제공하는 것을 확인했다. 이 검사에서는 전체 콘텐츠 생성기를 실행해 기존 폴더를 삭제하지 않았다.

## 재현

저장소 루트 PowerShell에서 설치한 Godot 콘솔 경로를 지정한다.

```powershell
$godotPath = 'C:\path\to\Godot_v4.7.2-stable_win64_console.exe'
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter2 -Profile prevent -Screenshots
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter2 -Profile recover -Screenshots
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite gameplay -Screenshots
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter -Profile prevent
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite chapter -Profile recover
& .\tools\run_gameplay_tests.ps1 -Godot $godotPath -Suite recovery
```

각 실행은 별도 임시 프로젝트와 Godot 저장 영역을 사용한다. 플레이어의 실제 저장과 Git 작업 파일을 테스트에 사용하지 않는다. `chapter2`는 같은 격리 프로젝트의 두 프로세스로 나눠 실행한다. 로그와 이미지는 `build/chapter2-qa/{prevent,recover}`에 남는다. 신규 콘텐츠만 다시 생성하려면 `python tools/gen_chapter2_content.py`를 사용한다.
